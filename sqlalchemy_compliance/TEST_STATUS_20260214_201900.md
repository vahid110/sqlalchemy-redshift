## What Was Fixed

**Schema Isolation in Reflection Methods**

When `schema=None` was passed to reflection methods, the code was grouping results from ALL schemas under a single None key, causing:
- Duplicate columns from tables with same name in different schemas
- Mixed constraint data across schema boundaries
- Incorrect reflection results

**Fix**: Use actual schema from query results (col.schema, rel.schema, con.schema) as dictionary key when schema=None.

**Impact**: 17 tests now passing, primarily in multi-reflection methods.
